# 知识库管理系统（eflink-wiki）方案 —— 独立系统版

> 状态：**v5 草案，待确认后开工**
> v5 变更：仓库结构调整——**单仓库 `eflink-wiki/`**，内分 `frontend/`（前端）与 `backend/`（后端），方案文档随仓库走。
> v4 已确认定位：小企业内部使用、无自助注册（管理后台建号）、单 jar + MySQL 交付、无多租户、Docker 延后。
> 日期：2026-09-12

---

## 一、定位与设计原则

面向**小企业内部使用**的独立知识库产品（对标 ONES Wiki / Confluence / 语雀的核心体验），私有化部署到企业内网单台服务器。

1. **运行期零外部依赖**——自带用户体系（管理员后台建号）、独立数据库，单 jar 即可运行；
2. **最小部署集 = 1 个 jar + MySQL 8**——前端产物打包进 jar（静态资源 + SPA 回退），上传走本地磁盘，缓存走进程内；Docker/Redis/MinIO 后续按需加适配器；
3. **产品内核 + 适配器边界**——认证（本地账号 ↔ 企业内部账号）、对象存储、全文检索均为 SPI，当前只实现默认档，扩展不返工内核；
4. **技术栈延续团队既有能力**——后端 Kotlin + Spring Boot 3.3.5 + JDK21 + jOOQ + MySQL（命令模式，与存量 backend 同风格、不共享代码）；前端 React 19 + Vite 8 + Tailwind 4 + zustand；编辑器复用五个 `@eflink-tech/*` npm 包（源码资产复用）。

---

## 二、总体架构与仓库结构

**单仓库 monorepo**（单一产品、前后端同生命周期发版、接口契约锁步演进）：

```
eflink-wiki/
├── README.md             # 项目说明、目录导航、快速开始
├── docs/                 # 本方案、接口约定、部署说明、变更记录
├── frontend/             # 前端：React 19 + TS + Vite 8 + Tailwind 4 + shadcn + zustand
│   ├── package.json
│   └── src/              # pnpm 工程；@eflink-tech/* 编辑器包 file: 软链接入
└── backend/           # 后端：Kotlin + Spring Boot 3.3.5 + jOOQ + MySQL（独立库 eflink_wiki）
    ├── settings.gradle.kts
    ├── wiki-core/        # 领域层（见 3.1）
    ├── wiki-contract/
    ├── wiki-store/
    └── wiki-app/
```

交付/运行形态：

```
企业内网服务器（JDK 21 + MySQL 8）
└── java -jar eflink-wiki-server.jar
     ├─ :8080  REST API（/auth /wiki /admin /upload ...）
     ├─ 前端静态资源（frontend 构建产物打进 jar，SPA 回退路由）
     └─ 本地磁盘上传目录（data/uploads/，路径可配）
首次运行：Flyway 自动建表 → 访问 /setup 创建管理员 → 管理后台建账号
```

配置：`application.yml` 内置默认值 + 可选外置配置文件/环境变量覆盖（数据库连接、端口、上传目录、产品名/Logo/页脚文案）。

**构建编排**：日常前后端独立构建互不影响；出包用根级 `scripts/build-all.sh`——先 `frontend: pnpm build` 得 `dist/`，再 Gradle 构建时把 `dist/` 拷入 `wiki-app/src/main/resources/static/`，产出单 jar。

## 三、后端设计（backend）

### 3.1 工程结构（命令模式，模块名产品化）

```
backend/
├── wiki-core/         # 纯领域层：Result、异常、领域模型、SPI 端口接口（零 Spring 依赖）
├── wiki-contract/     # API 契约：RestfulService 接口 + CO/DTO，分包 auth / wiki / admin
├── wiki-store/        # 持久化：Flyway 迁移脚本（schema 唯一来源）+ jOOQ 生成代码 + Repository
├── wiki-app/          # 组装：Spring Boot 启动、Handler、SPI 适配器、拦截器、前端静态资源回退
└── scripts/           # 构建/运行脚本、schema 说明
```

接口开发流程与存量一致：Command → RestfulService 接口 → Handler(validate+handle) → Repository。

### 3.2 账号体系（管理员创建制）

- **无自助注册**：账号一律由管理员在**管理后台**创建（用户名 + 初始密码 + 姓名），用户首次登录后可改密码；
- **系统角色**：`admin`（管理后台：用户管理、全局设置）/ `user`（普通用户，空间内再分 admin/editor/viewer）；
- **会话**：无状态 JWT access token（2h）+ refresh token（30d，DB 存哈希、轮换、可吊销）；图形验证码（hutool，状态存 Caffeine）；
- **首次启动引导**：`user` 表为空时 `/setup` 创建第一个管理员，完成后入口关闭；
- **忘记密码**：管理员重置（管理后台操作）；
- **企业内部账号对接（预留，不实现）**：`AuthProvider` SPI 端口预留；`user` 表设计保证后续可通过 Flyway 迁移加 `provider/external_id` 列，接入 LDAP/AD、钉钉、飞书、企业微信、OA 等（P2 按客户需求选型）。V1 密码锁定 BCrypt 单一实现。

### 3.3 基础设施 SPI

| 能力 | 默认实现（零依赖） | 可选适配器（后续） |
|---|---|---|
| 对象存储 | 本地磁盘 `data/uploads/` | MinIO/S3、七牛、OSS |
| 全文检索 | MySQL ngram FULLTEXT（标题 + 已发布正文） | Meilisearch |
| 缓存/验证码 | Caffeine 进程内 | Redis（多副本时） |
| 认证 | 本地账号（BCrypt） | LDAP/AD、钉钉/飞书/企微、OIDC |
| 缩略图 | Thumbnailator | — |

### 3.4 商业化/运营配套

- 产品名、Logo、登录页文案、页脚（ICP 等）：V1 走配置文件，P1 提供管理端可视化设置；
- **审计日志**（P1）：登录、发布、删除、权限变更入 `operation_log`；
- License 机制（P2，按商业化进度再定）；开源合规：Tiptap 只用 MIT 核心扩展、canvas-editor MIT、Univer Apache-2.0、Konva MIT、pptxgenjs MIT，上线前做一次依赖 license 审计。

## 四、数据模型（MySQL 8，Flyway 迁移脚本）

```sql
user          (id, username UNIQUE, password_hash, display_name, avatar,
               role,                                   -- 1 admin 2 user
               status,                                 -- 1 正常 2 禁用
               created_at, updated_at)
refresh_token (id, user_id, token_hash, expires_at, revoked, created_at)

-- 知识库核心
wiki_space    (id, name, icon, description, owner_id, visibility,      -- 0 私有 1 登录可读
               is_del, created_at, updated_at)
wiki_member   (id, space_id, user_id, role, UNIQUE(space_id, user_id)) -- 1 admin 2 editor 3 viewer
wiki_node     (id, space_id, parent_id DEFAULT 0, title, sort_order,
               current_version_id NULL,                                -- NULL=从未发布（草稿态）
               created_by, is_del, deleted_at, created_at, updated_at)
wiki_draft    (id, node_id, user_id, content LONGTEXT, base_version_id,
               updated_at, UNIQUE(node_id, user_id))
wiki_version  (id, node_id, version_no, title, content LONGTEXT,
               published_by, published_at, UNIQUE(node_id, version_no))
wiki_favorite (id, user_id, node_id, created_at, UNIQUE(user_id, node_id))
wiki_comment  (id, node_id, user_id, parent_id DEFAULT 0, content TEXT, is_del, created_at)
wiki_activity (id, node_id, space_id, user_id, action, created_at)     -- view/edit/publish/restore
```

- 树查询：邻接表 + `sort_order`，单空间全量拉取内存组树（数千节点无压力）；移动/拖拽改 `parent_id` + 批量排序；
- 页面正文（含嵌入块数据）= ProseMirror JSON；单块数据超大（excel >1MB）时再拆 `wiki_block_data` 表，接口形态不变；
- 全文索引：`wiki_version(title, content)` WITH PARSER ngram，仅搜已发布版本；
- 回收站：`wiki_node.is_del + deleted_at`，空间 admin 可恢复/彻底删除。

## 五、接口设计（统一 Result 封装 + 全局异常）

```
公开    GET  /public/config                       产品名/Logo/版本/功能开关
引导    POST /setup                               初始化管理员（仅 user 表为空时）
认证    POST /auth/login | /auth/refresh | /auth/logout
        POST /auth/change-password

用户    GET  /user/me | PUT /user/me              个人信息
管理后台（系统 admin）
        GET/POST        /admin/users              用户列表/创建账号
        PUT             /admin/users/{id}         改名/重置密码/改角色/禁用启用
        （P1：Excel 批量导入、空间总览管理、审计日志查询）

空间    GET/POST /wiki/spaces；GET/PUT/DELETE /wiki/spaces/{id}
        GET/POST/DELETE /wiki/spaces/{id}/members
        GET  /wiki/spaces/{id}/tree | /wiki/spaces/{id}/stats
页面    POST /wiki/nodes；PUT /wiki/nodes/{id}（改名/移动/排序）
        DELETE /wiki/nodes/{id}?purge=            删除/恢复/彻底删除
        GET  /wiki/nodes/{id}/page                已发布内容（viewer 可读）
        GET/PUT /wiki/nodes/{id}/draft            草稿读取 / 2s 防抖自动保存
        POST /wiki/nodes/{id}/publish             发布（生成不可变版本）
        GET  /wiki/nodes/{id}/versions[/{no}]；POST /wiki/nodes/{id}/restore
        GET/POST/DELETE /wiki/nodes/{id}/comments
其他    GET/POST/DELETE /wiki/favorites；GET /wiki/search?q=
        GET  /wiki/recycle/{spaceId}；GET /wiki/drafts（我的跨空间草稿）
        POST /upload                              本地磁盘存储
```

权限：拦截器解析 JWT → Handler 内校验（系统角色 + 空间角色 + 空间可见性）；写操作必须登录。Swagger 自测。

## 六、前端设计（frontend）

- 技术栈：React 19 + TS + Vite 8 + Tailwind 4 + shadcn + zustand + axios；
- **主应用布局**（对齐 ONES）：左栏（空间切换、搜索、主页、数据统计、**个人草稿区带"未发布"标记**、页面树拖拽排序、行内悬浮操作）+ 顶栏面包屑（逐级可点、星标）+ 正文阅读/编辑双态（标题、作者、最近修改时间、浏览次数）；
- **管理后台**（系统 admin 可见）：用户管理（创建账号、重置密码、禁用、角色）；P1 增加全局设置（品牌/注册策略类）、空间总览、审计日志；
- **块编辑器**：Tiptap 自建（ProseMirror JSON 落库；Pro 付费扩展不用，拖拽手柄/`/` 菜单自研）；基础块：段落/标题/列表/引用/代码块/图片/表格/分割线；
- **嵌入块**（复用编辑器 npm 包）：
  - draw / mindmap：内联只读渲染（Konva 组件），双击浮层/全屏编辑，保存写回块 JSON；
  - excel：Univer 只读模式内联，双击浮层编辑；
  - word / pptx：卡片块（标题 + 缩略图），点击全屏编辑页，保存后卡片刷新；
- **包接入**：`file:` 软链指向 `../../eflink-word/packages/word` 等存量模块 + `use:xxx:local/npm` 切换脚本 + vite `resolve.dedupe`（react/zustand/konva 单例），照搬存量模式；五个包的 StorageAdapter 注入"页面草稿桥接器"，块数据随页面草稿一起保存；
- 视口外嵌入块 IntersectionObserver 懒加载；Ctrl+S 立即保存；`/` 呼出块菜单；
- 页面清单：初始化引导、登录、空间主页（最近/星标/快速新建）、页面阅读/编辑、搜索结果、回收站、草稿箱、统计、空间设置（成员/信息）、管理后台（用户管理）。

## 七、实施分期

### P0 — 可交付内部使用的 MVP（预估 3.5~4.5 周）
1. **backend 骨架**：四模块工程、Flyway 首批迁移、jOOQ 接入、Result/异常/命令模式基座、本地盘存储、运行脚本
2. **账号**：/setup 引导、登录（验证码）、JWT + refresh、管理后台用户 CRUD（创建/重置/禁用/角色）
3. **wiki 核心域接口**：空间/成员/树/节点/草稿/发布/星标/回收站/搜索（ngram）
4. **frontend 骨架**：脚手架、布局骨架、引导/登录页、管理后台用户管理页、目录树（拖拽/新建/改名/删除/面包屑）
5. **块编辑器**：Tiptap 基础块 + `/` 菜单 + 自动保存
6. **嵌入块**：draw、mindmap、excel 内联块；word、pptx 卡片块
7. 草稿/发布双态 + 阅读态（浏览计数）+ build-all 出包脚本
> **里程碑：内网服务器上 `java -jar` + 建库 SQL（Flyway 自动执行），即可交付企业试用。**

### P1 — 协作与运营完善（预估 2.5 周）
版本历史（列表/diff 对比/恢复）、评论、空间成员管理页、数据统计页（浏览/编辑排行、热力图）、空间模板（另存为模板/从模板建页）、Markdown 导入导出、管理端全局设置（品牌可视化）、**Excel 批量导入用户**、审计日志、MinIO 适配器

### P2 — 按需演进
**企业内部账号对接**（LDAP/AD、钉钉、飞书、企业微信、OIDC，走 AuthProvider SPI）、Docker 镜像与 compose、License、Meilisearch、实时协同（Yjs）、演示模式、Word/PPT/PDF 导出、Confluence 导入

## 八、风险与待确认

| 点 | 说明 |
|---|---|
| Tiptap 交互自研量 | 拖拽手柄、`/` 菜单、占位符等自研估 +3~5 天；P0 首日 spike 验证 React 19 兼容性，若 BlockNote（Tiptap 封装）可用可省交互开发量 |
| MySQL 绑定 | ngram 全文检索是 MySQL 特性；如遇 PG/信创需求，检索实现已按 SPI 预留可替换 |
| 嵌入块内存 | 同页多个 Konva/Univer 实例靠懒加载 + 只读静态渲染兜底，开发中期做一次同页 10+ 块压力验证 |
| 企业账号对接选型 | V1 不实现，但 P2 启动前需确认目标企业的账号源（LDAP？钉钉？飞书？自研 OA？），影响 SPI 适配器选型 |
| monorepo 边界 | frontend 与 backend 依赖互不穿透（仅通过 HTTP 契约）；编辑器 npm 包仍来自仓库外的存量模块目录，软链路径在 frontend README 中写明 |

**已确认的定位决策**：小企业内部使用、无自助注册（管理后台建号）、单 jar + MySQL 交付、无多租户、Docker 延后、单仓库 `eflink-wiki/`（frontend + backend）。
